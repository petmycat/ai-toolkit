# Gen2 v2: standalone activator

V2 trains a small bank of input vectors through frozen Qwen and Ideogram models.
It replaces the trigger at its original caption locations. The initial experiment
has no diffusion LoRA, text-encoder adapter, or timestep/block gates. A known style
phrase is an optional **evaluation-only reference**, never a training target or
initialization source.

The approved specification is `docs/specs/gen2_trainer_v2.md`, pinned to SHA-256
`ec3e254c6638f1781faa449114acc17c1cc8aa454e6a5e79a4032b04ec4c7ae2`.
The user-owned reference and results under the repository's ignored `gen2/`
directory remain read-only. Code and these examples belong to the tracked extension.

## Run on the VM

From the repository root, validate and run the four-update mechanical smoke:

```bash
python -m extensions.gen2_trainer validate extensions/gen2_trainer/config/smoke_gen2_ideogram4_v2.example.yaml
python run.py extensions/gen2_trainer/config/smoke_gen2_ideogram4_v2.example.yaml
```

After the mechanical checks pass, the bounded pilot is:

```bash
python -m extensions.gen2_trainer validate extensions/gen2_trainer/config/pilot_gen2_ideogram4_v2.example.yaml
python run.py extensions/gen2_trainer/config/pilot_gen2_ideogram4_v2.example.yaml
```

These tracked configurations preserve the user's explosion prompt, trigger,
dataset path `/data/train/datasets/en_ig4_r1X1dOn9mA2`, output root
`/data/train/models`, and model identities from the working v1 configuration.
Use a new `config.name` for an independent run. The smoke retains the full training
resolutions and caption limit to exercise realistic memory costs.

Config-only validation checks values and incompatible flags without importing
models, loading weights, or accessing training images. **It does not establish
GPU compatibility or visual success.** The RTX PRO 6000 96 GB VM must validate the
real quantized forward/backward path, memory use, and sample outputs.
See [the v2 validation record](v2_validation.md) for the completed local checks
and remaining VM acceptance items.

## Pilot settings

- Four learned vectors, initialized independently from vocabulary statistics.
  Their magnitudes remain trainable. There is no semantic initializer string.
- 500 committed optimizer updates; every update trains the same token bank.
- Physical batch 1 with gradient accumulation 4: effective batch 4. Batch and
  accumulation are independent settings; the learning rate never scales silently.
- `gen2.optimizer`: AdamW, learning rate `0.0005`, epsilon `1e-8`, betas
  `[0.9, 0.999]`, weight decay `0`. AdamW8bit is also an explicit supported option;
  its GPU path still needs validation. Actual optimizer group settings are recorded.
- Constant learning rate. Native `train.optimizer`, `train.lr`, and scheduler
  overrides are rejected so there is one source of optimizer settings.
- BF16 computation and FP32 trainable masters. FP32 computation is supported when
  both `train.dtype` and `model.dtype` select it; FP16 requires an AMP path that is
  outside this initial implementation and is rejected.
- Gradient checkpointing in Qwen and the diffusion model. Frozen weights still
  participate in input-gradient computation and therefore need activation memory.
- `train.max_grad_norm: 0` disables gradient clipping. A positive value is an
  explicit gradient-norm cap; it never renormalizes the learned vectors.

The 96 GB card is the target environment, not a promise that arbitrary batches,
long captions, and high resolutions fit. Start at physical batch one. If it fails,
inspect the recorded sequence lengths, resolution, and model residency. Do not
silently lower the caption cap or resolution, skip batches, or advance the update
counter after an OOM. Low-VRAM/layer-offloading and compiled execution are rejected
until their input-gradient behavior is validated for this path.

## Trigger placement and caption integrity

`[trigger]` and the configured literal both invoke the learned bank. Every
occurrence expands to the same ordered four vectors at that location. Three
occurrences therefore use 12 learned positions while sharing 16,384 parameters
for the current Qwen width of 4096.

The native JSON normalizer and chat template remain in use. Original position
means the corresponding position in the normalized caption, not source byte
offsets. Training captions without a marker fail preflight; nothing is silently
appended. All original model weights stay frozen, but later ordinary token
features may change because causal attention can see the inserted activator.

The total cap is 3072 tokens including the chat wrapper and every marker
expansion. Runtime truncation removes ordinary content from the tail while
protecting learned positions and chat boundaries. Reports identify affected
inputs and omitted token counts. The original human-written caption files are
never rewritten. All evaluation modes use common retained content so the known
phrase's token length cannot accidentally change the scene being compared.

Image latents may be cached because the VAE is frozen. Text features cannot be
cached during training because they depend on the current vectors. Native caption
dropout, token shuffling, text-feature caching, extra loss terms, LoRA loading, and
other unused trainer options are rejected rather than silently ignored.

## Sampling, checkpoints, and resume

`sample.sample_every` controls visuals independently of `save.save_every`.
The pilot samples at 0, 100, 200, 300, 400, and 500; the smoke samples at 0, 2, and 4.
The examples use two fixed seeds and the same 1536 by 1024 explosion prompt, CFG
3.0, and 28 sampling steps as the working configuration.

Reference modes are the marker-removed base, optional named-phrase base, and the
initial random bank. The evolving mode is the trained bank. References can be
reused when their complete sampling identity matches. `gen2.evaluation.named_phrase`
is `Ghibli anime` in these user-specific examples; set it to `null` for a dataset
without a known descriptive benchmark. It never participates in training.

At update zero, the current bank is identical to initialization. The comparison
sheet labels that equality and reuses the initial image. With the two example
seeds, initialization generates six reference images; later sampling events
generate two current-activator images and place them alongside those references.
Console progress identifies the mode, seed, image count, and denoising progress.

The original frozen unconditional transformer is used for CFG in every mode.
There is no LoRA-strength sweep in the standalone activator experiment.

Retention is one rolling resume checkpoint and one final inference export.
`save.max_step_saves_to_keep` is fixed to one; vector masters are saved as FP32.
The package contains the bank, initialization/provenance, and compiler/model
identities, not frozen base weights. Resume state additionally carries optimizer,
RNG, data position, and committed update counters. Set `gen2.checkpoint.resume_from`
to a complete resume package to continue; do not substitute an inference-only
token file or a v1 checkpoint.

Outputs are under `/data/train/models/<config.name>/gen2_v2/`:

- `caption_token_report.json`: full compilation, protected truncation and positions.
- `run_manifest.json`: specification, model/tokenizer/data and initialization identities.
- `updates.jsonl`: loss, gradients, actual parameter changes, token norms and compact per-example evidence.
- `probes.jsonl` and `events.jsonl`: mechanical gradient and memory checks, frozen-weight checks and failures.
- `references/`: fixed images, reused across the run.
- `samples/uXXXXXXXX_comparison.png`: paired visual comparisons.
- `checkpoints/resume_latest/`: the one rolling resumable checkpoint.
- `checkpoints/inference_final/`: the final small inference package.
- `summary.json`: execution summary, with visual acceptance left for user review.

The initial mechanical checks deliberately select large image/text workloads and
long-caption batches from each expanded native resolution, run the real
Qwen-to-diffusion gradient path, and report actual memory. They preserve optimizer
state, data position, and training RNG. This is representative coverage, not a
guarantee that every future batch fits. Cached image preparation can precede these
checks; caption preflight runs before model weights are loaded.

### Inspect or use a saved package

```bash
python -m extensions.gen2_trainer inspect /data/train/models/gen2_ig4_r1X1dOn9mA2_v2_pilot/gen2_v2/checkpoints/inference_final
python -m extensions.gen2_trainer infer /data/train/models/gen2_ig4_r1X1dOn9mA2_v2_pilot/gen2_v2/checkpoints/inference_final --prompt "A tiger in [trigger] style" --output /data/train/models/v2_tiger.png --width 1024 --height 1024 --guidance 3 --steps 28
```

The default inference route invokes the learned bank only when the marker is
present. Explicit v2 diagnostic modes are `base`, `named`, `init`, and `learned`.
The example tiger prompt is a manual generalization check, not an added routine
sampling prompt or training caption.

### Optional full continuation acceptance

The following is more expensive than the ordinary smoke: it runs a full smoke,
a partial smoke, its continuation, and a fresh package load. It compares all
token/optimizer/RNG/data state and the reloaded image. Use a new output directory.

```bash
python -m extensions.gen2_trainer acceptance extensions/gen2_trainer/config/smoke_gen2_ideogram4_v2.example.yaml --output /data/train/models/gen2_v2_acceptance --split-after 2
```

It uses real VM models and data. CPU fixtures are not substituted by this command.
The default state comparison is exact; `--atol`/`--rtol` explicitly relax floating
tensor comparison if investigating platform nondeterminism. Package image parity
remains an exact check. A passing mechanical report does not claim style success.

## What counts as success

First establish finite/nonzero token gradients and updates, frozen-weight
integrity, exact marker accounting, a faithful no-marker native path, correct
accumulation, and save/reload prediction parity. Check representative long
captions and large image buckets, not only small examples.

The pilot then asks whether the trained activator matches or improves on the
known phrase's intended style while preserving the requested content, across
fixed seeds. The user's approximate style percentages are qualitative visual
judgments. Lower reconstruction loss, altered pixels, and nonzero gradients do
not prove this criterion. After the main prompt improves, use two additional
subjects absent from the training captions for the compositional acceptance check.

500 updates is a review point, not permission for an automatic long continuation.
If the bank changes but useful style does not emerge, investigate the next
specific hypothesis. A trigger-enabled Qwen adapter is a separately discussed
capacity extension; no v2 option silently enables it.
